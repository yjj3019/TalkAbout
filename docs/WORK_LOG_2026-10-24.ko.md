## 사용자 목표와 설계 경계

사용자 목표는 최초 한 번 PC를 연결한 뒤 방에서 **에이전트 선택 → 초대 버튼 → 실제 참여 → 대화·공유 자료 수신 → 응답/작업 결과 반영**으로 끝나는 것이다. 매 방마다 파일 다운로드·명령 복사·토큰 입력을 요구하는 수동 안내는 이 목표의 완성이 아니다. 기존 UI를 한 화면으로 모아 배포했던 작업은 사용자에게 거부됐으며, 사용성 문제가 해결됐다고 판단했던 보고는 정정한다.

외부 에이전트끼리는 같은 방의 자료와 다른 에이전트 결과를 실제 입력으로 받아 협업해야 한다. 공유 저장소가 있거나 신원만 등록된 것은 협업 증거가 아니다. 준비한 입력 참조, 인증된 worker의 결과 신고, 공급자 실행 증거, 모델의 이해·사실성은 서로 다르다.

기존 설계는 사람 소유자·에이전트 신원·방 멤버십을 분리한다. 외부 runtime이 이벤트를 가져가고 결과를 제출하며 플랫폼이 모델을 보유할 필요는 없다. endpoint/token 지급만으로 CLI를 실행시킬 수 없다. versioned REST, cursor, claim lease/attempt, 멱등 결과, 불변 산출물 버전, 명시적 관리 승인/감사, private 기본과 객체별 권한을 유지한다. 내부 LLM은 선택 사항이며 ACL·예산·종료 한도는 코드가 강제해야 한다.

## 중요한 구현 계약과 한계

- `server_start_v1` managed worker는 `POST /api/v1/rooms/{room_id}/tasks/{task_id}/start`의 one-shot 허가 후에만 runtime을 호출한다. 같은 응답 재전달은 `execute=false`, 새 key로 기존 예약을 덮어쓰지 못하며 HTTP client도 start를 자동 재시도하지 않는다.
- 시작 예약은 실제 provider 실행/이해 증명이 아니다. lease 만료·pause/close·topic/membership 변경 뒤에도 미확정 실행을 자동 재배정하지 않는다. 다음 phase도 보류한다. 방 종료는 외부 실행 종료 확인이 아니다.
- protocol을 협상하지 않는 legacy client까지 managed-worker의 journal 소실 방지를 보장한다고 주장하지 않는다. 명시적 uncertain 해소/재시도 API를 새로 만들지 않았다.
- 공유 문맥은 ACL-filtered 메시지, 선택된 불변 산출물 버전, 읽은 text 첨부, 출처·생략 범위와 고정 검토 대상을 포함한다. 임의로 생성한 요약을 사실처럼 넣지 않는다. 공급자 수신/모델 읽음의 증명은 아니다.
- F18은 동의 회수가 서버 실행 허가보다 먼저 반영된 경쟁을 막는다. 이미 runtime에 전달된 자료 회수나 start 이후 외부 호출 취소를 보장하지 않는다. 이전 읽기 metadata는 보수적으로 검사한다.
- 비공개 `_file_reads`가 재임대 응답에 노출된다는 의심은 철회했다. `text_files.public_task`가 `_file_` 접두사 필드를 제거하고, Core가 정제 후 멱등 응답을 저장한다. API/MCP는 그 반환값을 전달한다. 이 특정 경로를 새 실기 검사한 것으로 보고하지 않는다.
- SQL 테이블 마이그레이션 없이 기존 task/room JSON에 실행·입력·읽기 metadata를 추가했다. 구버전은 새 세션/hold/uncertain/동의 검사를 강제하지 못하므로 schema 호환만으로 rollback 안전을 판단할 수 없다.

## 미완료와 정확한 차단

### 버튼 초대와 실행 지원

`paired_runner.py`와 그 backend 테스트 파일은 존재하지 않는다. `runner_client.py`는 아직 없는 `runner/reservations` API를 참조하는 독립 초안이고 `runner_bridge.py`도 콜백 모듈일 뿐 UI/API/CLI와 미연결이다. 가짜 시험 통과는 기기 pairing, 자동 초대 수락, native 실행, 영속 예산 원자성 또는 실제 참가 성공을 입증하지 않는다.

Codex/Claude의 기존 어댑터는 소스에 있으나 실제 연결 수용 검증은 미완료다. Grok는 native 인증 및 API-key 작업공간 격리 검증 미완료로 차단한다. Muse Code 어댑터는 없으며, 설치 메타데이터와 공식 제품을 대조한 것과 사용자가 원하는 대상이 그 CLI인지 확인하는 것은 별개다. **Muse Code CLI와 Muse 개인 앱 중 사용자 대상 확인은 대기** 상태로 보존한다. 공식 MSP 인터페이스가 있다고 해서 현재 설치 버전의 Windows 연동이 검증된 것은 아니다.

### 코드 작성 심사와 실제 실행 승인

토큰 생성·보관 기능의 소스 구현과 가짜 시험에 대한 직접 승인 뒤에도 backend 파일 작성이 거절됐고 미실행이다. 이유는 grant 영속화, raw token 생성, credential 저장과 API 반환 기능의 코드가 실제 발급/보관 금지와 충돌한다고 심사된 것이다. 보존된 근거에 별도 승인 요청 ID는 없어 확인할 수 없다.

함수 정의/소스 작성과 실제 발급·저장·계정 연결을 분리해 심사 범위를 정리해야 한다. 같은 거절을 다른 파일명·도구·구조로 재시도하지 않았다. 소스 허용을 받기 위해 실제 계정 권한까지 넓혀 승인받아야 한다고 제안하지 않는다. 이후 보존 지시에서도 거절된 인증 코드를 작성하거나 실행하지 않았다.

### 실제 시험과 PostgreSQL

과거 실제 연결 시도는 HTTP 503과 함께 불확실 1회로 남았다. 오류 본문이 없어 정확한 원인은 미확정이며 실제 모델 응답·서버 결과 수신·재연결 성공을 입증하지 못했다. 미사용 2회와 원본 증거는 로컬에 보존했고 새 예산으로 재해석하거나 자동 재시도하지 않았다. 후속 진단은 허용된 오류 분류·상태·경로 템플릿·단계만 기록하도록 범위를 제한했다.

마지막 첨부 수정의 PG 검증은 환경 준비 단계에서 미완료다. 디스크 부족이나 잔존 소유 PG 프로세스라는 근거는 없었고 성능/메모리 CIM 읽기는 현재 실행 환경에서 실패했다. 제한시간·동기화·가드를 바꿀 수 있는 근거는 없었다. 해결됐다는 새 증거 없이 같은 초기화를 반복하지 않는다.

실제 토큰 발급·보관, 기존 CLI 계정 사용/갱신, 실제 외부 모델 호출, 설치·자동시작·MCP 설정 변경은 현재 실행하지 않는다. 이전 제안은 승인이 아니다. 제품 검증에 필요하다고 정리한 후속 제안은 '기존 Codex/Claude 두 계정, 새 격리 API/PG, private 방 2개, 30분 기기 2개+방 4개 인증, DPAPI 시험 vault, 합성 자료, 앱 dispatch 최대 10회·각 120초·전체 25분, 추가 과금 여부 확인 불가 시 중단, 철회·방 종료·소유 프로세스 정리'였다. 이것을 실행 허가로 사용하지 않았다. CLI 내부 재시도/사용량과 금액 하드캡은 앱 dispatch 한도와 다르다.

## 공개 보존의 포함·제외

포함: 이 프로젝트의 기존 관련 소스·테스트·지원 문서와 비식별 요구사항/결정/감사/검증 이력. 미완성 파일은 미연결 상태를 명시해 보존한다. 변경 목록과 검증 선택/제외는 동반 JSON에 기록한다.

제외: 원본 운영 DB, 임시 DB cluster·SQLite journal·WAL/SHM, 계정/토큰/비밀번호/인증 cache, 원본 민감 로그·응답·복구 이미지, 개인 계정 식별정보, 사용자 컴퓨터 절대경로, 다른 프로젝트 자료, 내부 에이전트 지침·사적 작업 메모, 외부 프로젝트 checkout 및 생성물. 로컬 원본 보고서는 그대로 업로드하지 않고 이 요약에 필요한 사실만 반영했다.

저장 전 원격 기준과 배포 트리거를 읽기 전용으로 확인했다. 저장소 워크플로의 push 대상은 main과 별도 기존 기능 브랜치뿐이고 이 작업 브랜치는 포함하지 않는다. 운영 배포 job은 없으며 등록된 webhook/deployment 조회도 0건이었다. 워크플로·보호 규칙·hook을 변경하지 않았다. 이 문서 저장과 작업 브랜치 push는 main 병합 또는 운영 적용이 아니다.
