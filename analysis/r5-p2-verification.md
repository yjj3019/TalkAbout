# R5 P2 성능 개선 및 검증

## 범위와 구현

- 첨부 파일을 읽은 워커의 재검증은 방 전문 대신 `GET /api/v1/rooms/{id}/fence?task_id=...`를 요청한다. 방 상태·세대·요청자 멤버십 revision과 한 작업의 lease 필드만 전송한다. 파일 동의 목록은 종전처럼 별도로 재확인한다. 404를 반환하는 구버전 서버에서는 기존 방 전문 조회로 대체하며, 그 외 오류에는 대체하지 않는다.
- 조회는 다른 작업공간이나 비활성 멤버, 방 제한 자격증명을 차단하며, 에이전트가 다른 에이전트의 작업 세부정보를 열람하지 못하게 한다. 누락되거나 보이지 않는 작업은 null이며 워커는 stale로 처리한다.
- 수동 시작 시 후보 워커들의 자격증명을 한 번에 조회한다. 방 변경 트랜잭션의 기존 PostgreSQL 연결을 사용해 중첩 풀 체크아웃을 피하며, 완료 메시지의 런타임 검증도 같은 경로를 사용한다.
- R4에서 이미 완료한 커서 인덱스·만료 정리 및 워커 long-poll은 중복 변경하지 않았다. 페이지네이션은 제품 정책 결정이 필요하므로 제외했다. DOM 패치와 언어별 라벨 분할은 후속 항목이다.

## 검증

- Python: `tests/test_p2_performance.py`, `tests/test_r4_perf.py`, core, PostgreSQL, worker, text files, community, identity, runtime checks 및 관련 권한·예약 테스트 등 15개 파일 **185 passed, 1 warning**. 로컬 격리 PostgreSQL 18.6 픽스처와 Windows 임시 디렉터리 호환 shim을 사용했다.
- JavaScript: `tests/*.mjs` 12개 파일을 각각 Node 프로세스에서 실행하여 전부 통과했다.
- 문서: `tools/docs_check.py` 결과 **0 new, 0 known**; `git diff --check` 통과.
- 실 첨부파일 워커 테스트는 새로운 fence 경로와 구버전 서버의 404 대체 경로를 확인한다. 중간 pause·동의 철회·lease 만료·stop 시 런타임 호출이 차단되는 기존 테스트도 통과했다.
- PostgreSQL 풀 크기 1에서 수동 시작이 성공하고 자격증명 조회가 트랜잭션 연결로 한 번 수행되는 것을 확인했다. 자격증명 유효성의 배치/단건 동등성은 취소·만료·scope·room·runtime 등 조건을 대상으로 테스트했다.
- 예제 fence JSON은 테스트에서 1,024바이트 미만이다. 이는 응답 크기 계약이지 운영 트래픽이나 레이턴시의 실측 개선율이 아니다.

## 제약 및 라이선스

- fence는 지정된 방 한 개만 조회하고 이벤트 이력은 생략하지만, PostgreSQL 방 JSON payload 전체는 여전히 읽는다. SQL 컬럼 단위 projection, 실제 대규모 데이터/네트워크 측정과 동시 부하 테스트는 수행하지 않았다.
- 방 시작 전 자격증명 철회나 연결 상태 변경이 동시 발생할 때의 완전한 직렬화는 이 변경이 보장하지 않는다. 종전 구조에도 존재하던 경합이며, 보안 정책과 락 순서 설계 및 별도 동시성 검증이 필요하다.
- 전체 표준 회귀 스위트와 실제 브라우저·운영 서버 시험은 이번 P2 범위에서 실행하지 않았다. 이 환경의 이전 전체 스위트는 Windows ACL/DPAPI 및 named-pipe 제약으로 실패했다. CI 성공이나 운영 성능 향상으로 간주하지 않는다.
- 변경 로직은 TalkAbout 기존 계약을 토대로 독자 작성했다. 비교한 외부 저장소의 소스는 복사하거나 번역하지 않았으며 새로운 외부 의존성은 추가하지 않았다.
- 로컬 `.git` 쓰기 권한 거부로 커밋은 생성하지 않았고 기존의 관련 없는 변경은 그대로 두었다.
